| [Dating Compatibility Embedding System](https://github.com/sjordan1975/dating-compatibility-finetuning) | I fine-tuned a sentence transformer with contrastive loss to predict relationship compatibility from dating profile text, showing that compatibility is not the same as textual similarity. The pre-trained model performed poorly (AUC 0.40, worse than random), but after fine-tuning, performance improved to AUC 0.91 with Cohen's d = 2.17, which is a very large effect size. After seven rounds of tuning hyperparameters like epochs, learning rate, batch size, and warmup, accuracy plateaued at 83%. This suggests that the limit comes from the data itself, not the training setup. The main takeaway is that generic profile language, such as "I value honesty," makes it hard for the model to learn useful patterns. To improve further, we need more specific training data rather than more engineering. <br><br>Python · SentenceTransformers · UMAP · HDBSCAN · Pydantic · Matplotlib · pytest |
| [Digital Clone: Multi-Agent Communication System](https://github.com/sjordan1975/digital-clone-multi-agent) | I built a five-agent LangGraph pipeline that learns how a specific employee communicates from real email history and answers knowledge-based queries in their style, routing low-confidence questions to a human via calendar booking. The system extracts 11 stylometric features from 2,156 Enron emails, builds a 530K-chunk FAISS index from CS textbooks, and evaluates responses across three dimensions: style (cosine similarity), groundedness (LLM-as-judge), and confidence (algorithmic). The main finding is that post-hoc style rewriting made scores worse, not better; the raw output scored 0.678 on style versus 0.565–0.599 with the rewriter. This confirmed an architectural constraint: generating grounded technical content and rewriting it into a business executive's terse email voice are competing objectives at the feature level. High style targets are structurally difficult to achieve when the employee has never written in the query domain. <br><br>Python · LangGraph · LiteLLM · FAISS · SentenceTransformers · Instructor · Pydantic · Matplotlib · pytest |
| [Customer Sentiment & PM Intelligence](https://github.com/sjordan1975/customer-sentiment-pm-intelligence) | I built a four-agent pipeline that ingests 4,742 reviews across Amazon, Yelp, and App Store, scores sentiment and pain intensity, discovers themes via LLM map-reduce, aligns them to a roadmap with semantic embeddings, and surfaces priority-ranked gaps. The sentiment stage produced a clean technical win: refining a three-class prompt plateaued at 79–82% because changes just redistributed errors across class boundaries; reframing the output to predict a 1–5 star rating directly and collapsing to three classes algebraically landed 84.5% (Wilson 95% CI [83.5%, 85.5%], 95.5% within ±1 star). But the deeper takeaway came from stepping back. The spec asked for multi-source ingestion AND alignment against a single product roadmap; quietly antagonistic when the corpus spans three unrelated domains. Themes correctly cluster around domains, not features, and zero gaps cleared the 0.6 priority threshold (confirmed by two independent formula re-tunes). That's a structural finding, not a tuning failure. The engineering judgment isn't "can we make the math work?" (we can) but "are we asking the right question of this data?" Surfacing that honestly is worth more than fabricating a flattering result. <br><br>Python · CrewAI · DSPy · LiteLLM · Instructor · OpenAI · Pydantic · Streamlit · Matplotlib · Seaborn · pytest |
